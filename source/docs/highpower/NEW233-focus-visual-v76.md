# TEST0.76 — optional NEW233 focus material

This is a client-only presentation sample for the already implemented obstacle branch. It does not add energy-node interruption or entity damage. The ten-block whitelist, 36 m distance, ten real server ticks of focus, tool/loot/permission transaction and all payment/cooldown/protocol classes remain unchanged from TEST0.75. The two closed-runtime certification classes require exactly one current-version string update from .75 to .76; an explicit constant-pool normalization must reproduce their full previous class bytes. This is a version identity exception, not a claim that those two class files are byte-identical.

## Controls and interpretation

`/aca_vfx2 point_meltdown on`, `off`, or `status` controls only this client's optional presentation. The persistent setting defaults OFF. OFF and unavailable resources use the complete TEST0.75 renderer.

The receipt's actual eye-to-surface centerline is retained. In first person an eye-origin ribbon is viewed end-on and cannot show a long beam merely by making it wider. Readability therefore comes primarily from the confirmed target surface: three open contracting arcs and a small original green/ivory heat core. Their decorative footprint is not an enlarged mining area. Every surface fragment is clipped to the same native face. Moving packets decorate only the accepted segment and do not predict a new route.

Contraction uses accepted focus ticks only. An independent bounded, pause-aware client tick counter animates decoration; it does not advance focus, reset input, extend the lease or manufacture completion. Only CONFIRMED native removal may produce the original six-tick short flash. Cancellation/unavailable receipts clear it through the existing state machine.

## Assets and rendering

Original ACA PNGs are reused unchanged: `effects/mdray_small/blend_in.png`, `tile.png`, `blend_out.png`, `effects/mdball/glow.png`, `effects/mdball/0.png`, and `effects/glow_line.png`. Original asset attribution remains in the repository. No external-mod assets or dependencies are added. The enhancement is new geometry and shader-driven material, not newly painted texture artwork.

An isolated soft-alpha shader avoids the vanilla 0.1 discard that removed the old translucent shoulder. Native depth testing remains enabled and depth writes are disabled for the enhancement. Face and near-plane clipping interpolate texture coordinates together with positions. World coordinates are subtracted from the camera in double precision before float upload.

A single 4096-vertex limit covers the entire enhanced scene after clipping, at most four contexts, zero spawned particles. It replaces the classic scene; it is not added on top of the old 2048-vertex budget. Pre-submit capacity/resource failure selects the complete classic frame. A failure after partial GPU submission disables enhancement for the next frame without drawing another full classic frame on top.

## Verification limits

Geometry/source/class identity checks are not proof of beauty or GPU performance. Actual OFF/ON game recordings and first/third-person, daylight/night, near-eye/occlusion/cancel/reload observations must be recorded independently. Existing partial gameplay, dedicated-server/multiplayer, default-hardware, historical guard and TEST0.73 movement incident limitations remain. This document records the intended contract; final acceptance is reported with the candidate evidence.

## Recorded candidate observations

Normal-20-TPS controlled stone fixtures were recorded through the native screen-recording UI. The same first-person day view shows a clearer local green/white focus core with ON; this is a modest tool-feedback improvement, not a large-area attack. Night and near-eye runs, resource reload, preview expiration followed by a fresh successful cast, and a solid bedrock obstruction were exercised. The third-person front camera put the target behind the camera: useful oblique beam-body appearance is still unverified. No side-view quality claim is made from that recording.

After normal save/re-entry, inventory, native HP/abilities/position, classic CP, q/Q, precise HP/S and payment data were unchanged; only old global tick/armor phase counters advanced. The original 2085-test native suite and complete `check` are reported separately with retained failures. Full animation aesthetics, default hardware performance and multiplayer acceptance are not established by these controlled clips.
