# 跨模组战斗接口

适用于 Ag 重生 a3.84、Minecraft 1.21.1 和 NeoForge 21.1.252。调用方在逻辑服务端线程上操作实体，原版与目标模组继续负责保存实体状态。

## 发起一次攻击

已有调用方可以继续使用 `NativeCombatDamage.hurt(target, source, amount)` 并取得实体原生的布尔返回值。需要扣费或显示命中结果的技能可以改用 `hurtDetailed`。这两个入口都调用一次目标的受击方法。

```java
var receipt = NativeCombatDamage.hurtDetailed(target, source, amount);
if (receipt.affected()) {
    // 由该技能提交本次施法自己的费用或命中反馈。
}
receipt.whenKilled(target, dead -> recordConfirmedKill(dead.getUUID()));
```

`healthSpent` 记录本次攻击可归因的实际扣血。`absorptionSpent`、`temporarySpent`、`dnaSpent`、`baseSpent`、`targetShieldSpent` 分别记录原版吸收、技能盾、外部 DNA 盾、基础盾和目标自行公开的额外盾。当前生命仍可从 `before` 和 `after` 核对。事件取消、图腾、死亡救援以及目标公开的阶段各有独立字段。即时移除的击杀在 `killed` 中记录。进入延迟死亡的目标可用 `whenKilled` 接收同一实体因该击死亡后的移除通知。复活、卸载、换维和其他来源接手死亡会结束跟踪。

自写技能可调用 `hurtSkill` 或 `hurtSkillDetailed`。普通入口先让目标的受击方法处理。目标在原生伤害交易开始前拒绝该次技能，且生命和吸收均未变化时，技能可再以非接触伤害进入原生结算。已进入交易的改伤和取消继续有效。非接触回退的受击事件没有直接命中实体，技能自己的来源和死亡文案仍可追溯。

`CombatControl.hold` 按世界时间控制非玩家实体的更新和攻击。玩家继续运行原版更新，其位移输入由服务端暂时拦截。控制前可调用 `CombatControl.canAffect` 检查霸体、阵营和 PvP 规则。

## 有独立生命或战斗阶段的实体

通过 `RegisterCapabilitiesEvent.registerEntity` 给相应实体注册 `CombatDefense.CAPABILITY`。进入本模组前，目标可以照常拒绝狂怒、无敌或来源不合格的攻击。`withoutDamageCap` 计算保留合法倍率、移除本次固定封顶后的金额。例如，受到 1,000 万点输入、阶段保留 4% 时，提供者返回 40 万。

独立血池的所有者可在自己的原有扣血位置调用 `CombatDefense.settledDamage(target, source, originalAmount)`。在已匹配的原生交易中，它返回 NeoForge 最终金额。取消或同一笔已提交的重复扣款返回零。目标按此金额结算自己的盾、血、救援与阶段切换。原生入口、Mod 事件和技能均使用同一个 `DamageSource` 实例。

`observe` 可以返回 `CombatDefense.Pools`，公开权威当前生命、本模组额外持有的盾余额及阶段名。`boss` 或整合包实体标签 `c:bosses` 可以声明首领身份。六石响指从整合包保护规则允许的生命中选取目标。选中的非玩家实体按原生移除流程卸载，选中的生存玩家进入死亡流程。

较大的已加载实体会补充进 `CombatTargeting` 的范围和射线查询。近战复核用 `visibleWithin` 核验身体或部件表面到施术者的距离与遮挡，已招募成员同样可从近侧肢体接受范围指令。

## 可封印的防御装备

用 `RegisterCapabilitiesEvent.registerItem` 给实际装备注册 `EquipmentSeal.CAPABILITY`。装备实现的 `permits` 决定本次施法能否封印该穿戴者或持有者。现实宝石的收缴技能在命中时请求 200 游戏刻的封印。

装备自己的补血、补发物品和死亡救援逻辑在生效前查询 `EquipmentSeal.active(wearer)`。截止时刻存在实体持久化数据中，以服务器主世界的游戏时间计时。该接口保留物品堆及其组件。能够恢复这三项防御的代码仍由对应装备持有。

## 未声明接口的目标

普通实体直接走原生流程。对于可以验证的单次封顶和唯一同步生命写入，兼容层在既有伤害交易内结算。无法确认语义的私有写入沿用该实体的实际行为，战报显示能观察到的结果。完整判例位于 `qa/CombatContractAcceptance.java`，实际专服双客户端取样位于 `qa/CombatNetworkProbe.java` 和 `qa/CombatNetworkClientProbe.java`。

光影旁观测试使用两个独立客户端。用 `python qa/check_combat_beam.py <双客户端测试目录>` 检查同一事件后的七个实机帧。脚本需要 Pillow，取景和准星位置须与 `CombatNetworkProbe` 的测试场景一致。
